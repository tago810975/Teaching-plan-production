# 开发交接

给接手本项目的开发者（包括新开的 AI 对话）。**开始任何工作前先读完这份文档**，再读 `README.md`
和 `docs/技术选型.md`。最后更新：第 12 版工程格式，445 个测试。

## 1. 项目是什么

教学案制作软件（桌面应用，先做 Windows，后移植 macOS）：导入题目 Word 文档 → 自动识别题目 →
在软件中编辑与排版 → 一份工程同时导出教师版（教案）与学生版（学案）Word。
用户是一位物理老师，文档来自题库，格式杂（MathType 公式、WPS 绘图、EQ 域等）。

## 2. 技术栈与运行

Electron 44 + React 19 + TypeScript 6 + electron-vite；公式用 MathLive（编辑）、temml（LaTeX→MathML）、
自写的 OMML/LaTeX/MathML 互转；docx 读写直接操作 OOXML（JSZip + @xmldom/xmldom）；MathType 用 cfb 读 OLE。

```bash
npm install     # 每次 git pull 后都要执行，依赖常有新增
npm run dev     # 开发版
npm test        # vitest，全部应通过
npm run typecheck
```

用户在 Windows 上用 `git pull` + `npm install` + `npm run dev` 测试，**所以每个功能做完必须提交并推送**。

## 3. 架构：一条贯穿始终的原则

```
工程数据 (Project)  ──build.ts──▶  文档中间表示 (DocIR)  ──▶  预览 (React)
                                                         └─▶  Word 导出 (docx-writer)
```

- **所有排版规则只写在 `src/core/document/build.ts`**（题号、选项分列、教师/学生版取舍、留白、跨页、
  图片位置、知识点、综合题）。预览与导出只读 DocIR，不得各自另写规则——这是“预览与导出一致”的保证。
- `src/core/` 是纯逻辑，不依赖 Electron 与 DOM，可直接用 vitest 测试。界面在 `src/renderer/`，
  文件读写在 `src/main/`，二者通过 `src/shared/ipc.ts` 定义的接口通信。
- 样式数值在 `core/document/styles.ts`，取自模板 `resources/templates/physics-default/template.docx`
  的 styles.xml（该模板由 `scripts/build-template.mjs` 从参考样例生成）。

## 4. 数据模型要点

内容块 `Block`：`title | section | topic | paragraph | question | knowledge | composite`。

- **question** 有 stem/options/subQuestions/figures/answer/knowledgePoints/keyPoint/difficultPoint/analysis/layout。
- **knowledge**（知识点）：标题 + 内容 + 插图 + 版式；**composite**（综合题）：标题 + 可选背景 + 小题（完整 question）+ 共用答案与详解。
- **图片位置** `FigurePlacement`：`below | right | right-items | below-item | below-all | free`，
  锚定段落 `anchorParagraph`、上下偏移 `offsetYEmu`、自由位置的 `offsetXEmu`。右侧图只能上下移动，自由图四周型环绕。
- 富文本是 `Inline[]`（文字/公式/图片/填空）。**公式同时保存 `omml`（Word 导入的原始）与 `latex`（软件中新建或改过的）**：
  未改动的公式导出时原样写回 OMML，零损失。
- `RichParagraph.format`：首行缩进、对齐、段后空行 `spaceAfterLines`、段前换页 `pageBreakBefore`。
- **题目总数**按题号计（`countQuestions`）：独立题目与综合题的每道小题各算一道，综合题本身不算。首页列表与导入提示共用。
- **选项图片**就是选项内容里的行内图片（`ImageInline`），没有单独的数据结构；缩放直接改它的 `widthEmu/heightEmu`，
  因此不涉及工程格式版本。DocIR 中选项图片的 run 带 `optionRef`（题目 ID、第几个选项、第几个行内元素），预览据此回写。
  所有缩放都保持各图自身宽高比；“统一大小”是把每张图放进基准图的宽、高之内。
- **格式预设**（`project.presetId`，见 `core/presets`）：标题三级（大标题、栏目标题、题型分组）的格式、常用栏目名、
  作业单格式、知识梳理强调格式、导入规则、难度等级都在预设 JSON 里。`buildDocument` 把 `presetStyles(preset)` 放进
  `DocIR.styles`，预览通过 `preview/styles-context.ts` 读取；导出时 `heading-styles.ts` 把这三个样式的格式写进模板
  styles.xml 的同名样式（按 ECMA-376 顺序排列子元素）。物理教学案 V1.0 与模板原样一致，有测试对照。
- **作业单**是一个块（`worksheet`：标题 + 姓名栏各项），排版为“段前分页的大标题、空行、姓名栏（制表位 3980/7980、
  下划线填写处）、空行”，其后题号从 1 开始——与示例文档 `教案_T_动态圆专题.docx` 一致。导入时由 `preset-rules`
  把“作业单-…”大标题与其后的姓名栏合成。
- **格式工具**（`panels/FormatToolbar.tsx`）：文本框聚焦时登记为作用对象，按钮与快捷键调用 `markup.ts` 的
  `applyFormat`（切换加粗/倾斜/下划线，或设定颜色）改写标记文本；改完后整个输入框的标记按出现顺序**重新编号**，
  objects 表只保留用到的（编号只在编辑时存在，不进入保存的数据）。颜色取自预设 `textColors`
  （红 C00000、黑＝去掉颜色、蓝 2F5597）。公式的 `bold`/`underline`/`color` 在导出时由 `export/math-marks.ts`
  写进 OMML：加粗、颜色写进每个 `<m:r>`；**下划线不能逐字加 `w:u`**（分式的分子、分母会各有一段高低不同的线），
  而是把整个公式放进底部的“下横线”结构 `<m:bar><m:pos m:val="bot"/>`，预览中对应公式整体的下边框。
  带格式的 LaTeX 公式在输入框中必须写成 ⟦公式N⟧ 标记（写成 $…$ 会在改文字时丢格式）。
- **重点**（预设 `keyPoint`，`markup.ts` 的 `KEY_POINT_MARKS`/`isKeyPoint`）：红色 C00000 + 加粗 + 下划线这一组格式，
  知识点的格式工具栏中有快捷按钮（`applyFormat` 的组合操作），标记写作 ⟦重点N:…⟧。**计划中的默写单**按这组格式
  找出挖空内容（文字与公式），替换为等宽的下划线空白。
- **撤销 / 重做**（`state/store.ts`）：`reduceAt` 在每次改动工程或资源前，把修改前的 bundle 与当时的选中项
  记入 `history.past`（不可变数据，快照共用未改动部分），最多 200 步；同一处的连续修改（`mergeKey`：同一内容块、
  标题、页眉文字、版式）间隔不到 1 秒合并为一步。撤销后 `revision + 1` 让属性面板重新读取，并按 `focusRequest.caret`
  把光标放回原输入框（输入框的 `data-field-id` 由 `useFieldFocus` 写上）。`dirty` 由“当前工程是否就是
  `savedProject`”决定。**新增会修改工程的动作时，想合并连续修改就在 `mergeKey` 中加一项。**
  菜单的撤销 / 重做用 `registerAccelerator: false`，快捷键由 Editor 在捕获阶段统一处理；对话框中交还浏览器原生撤销。
  界面层的测试放在 `test/renderer/`（由 tsconfig.web.json 检查）。
- **预设的类型**（`kind`）：`lesson` 教学案、`handbook` 知识点手册。知识点手册导入用 `recognize-handbook.ts`
  （大标题 + 知识点，不识别题目），添加菜单只有知识点、正文、大标题。`header.variantSuffix` 决定页眉右侧是否加
  “(教案)/(学案)”；`header.left` 是新建时页眉左侧的文字。
- **默写挖空**（预设 `dictation`，`build.ts` 的 `blankKeyPoints`）：学生版中加粗且为指定颜色（C00000/FF0000）的
  文字与公式换成填空横线（`blank` run，导出为带下划线的全角空格），相邻的合成一条，至少 `minChars` 个字宽、
  字多时为字数加一。导入时 EQ 域与 OMML 公式保留红色加粗（`docx-reader.ts` 的 `mathMarks`/`ommlMarks`），
  否则公式无法判断是否挖空。示例与分析见 `reference/samples/物理知识点手册_光/`。
- **表格**（`core/model/table.ts`）：行内元素 `type: 'table'`，独占一段，可出现在任何富文本中；单元格内容为富文本，
  合并单元格按 HTML 方式记录（起始单元格写 colSpan / rowSpan，被覆盖的位置不出现），`layoutTable` 算出每格的占位。
  导入（`docx-reader.ts` 的 `readTable`）：gridSpan → colSpan，vMerge 续行计入上方的 rowSpan；导出（`docx-writer.ts`
  的 `table`）：被覆盖的位置写 vMerge 续行单元格，含表格的段落先写其余内容再写 `<w:tbl>`，正文不能以表格结尾。
  预览中含表格的段落整块分页。输入框中显示为 ⟦表格N⟧，由 `panels/TableEditor.tsx` 编辑。
  增删行列（`insertRow` 等）按网格计算：插入位置穿过合并单元格时把它拉长 / 拉宽，删除时缩短 / 变窄，
  用 `rebuild` 按格子坐标重排各行的单元格；插入列时新列取相邻列宽。
  预览中拖动列边框（`DocParagraphView` 的 `TableView`，回调经 `preview/table-resize.ts` 的上下文）：拖动中只改本地
  草稿，松开后 `set-table-widths` 写回。**移动与松开要在 window 上监听**——拖动中表格可能因变高被排到下一页而
  重新创建，挂在手柄上的监听会失效，松开时就不会写回。
- **三级标题（大标题、栏目标题、题型分组）**：`pageBreakBefore` 从新的一页开始（文档开头的不另起），
  `restartNumbering` 题号重新开始，在属性面板“版式”中设置。分页（`paginate.ts`）中“与下段同页”连成的一组
  遇到段前分页的段落就截止——否则紧跟在另一个标题后的标题（如“例题精讲”后的“放缩圆”）不会另起一页。
  zod 校验因递归（单元格内是富文本）对 inline / richParagraph / tableInline 显式标注了类型。
- **预览中选中文字改格式**（`preview/SelectionToolbar.tsx`）：排版时文字记下来源 `DocRun.src`（段落路径 +
  第几个行内元素，表格单元格中的也记），预览元素写 `data-src-*`；选区按这些标记换算为 `TextRange`（跨段落时
  每段一个），状态动作 `format-range` 用 `markup.ts` 的 `formatParagraphRange` 修改，合为一步撤销。
  有选区时点击预览不跳到输入框（否则选区被取消）。
- **快捷版式窗口**（`BlockQuickMenu.tsx`）：预览段落与大纲条目右键时由 Editor 打开（同时选中该内容），按内容类型
  显示常用版式（题目：难度、选项排布、整题同页、留白、从新页开始；知识点 / 综合题：同页、留白、新页；三级标题：
  新页、题号重新开始）及上移、下移、删除。全部经已有的 update-block / move-block / delete-block，可撤销。
  右键图片时（`preview/image-menu.ts` 的上下文，`FigureImage` 中阻止冒泡）弹出 `ImageQuickMenu.tsx`：题图 / 插图的
  位置、段落或小问、宽度、顺序、删除（规则与属性面板共用 `panels/figure-options.ts`），选项图片的宽度、一起缩放、
  统一大小。窗口外壳为 `BlockQuickMenu.tsx` 的 `QuickPopover`。
- **环绕图的层级**：段落是 `position: relative`，后面的段落框会盖住前面段落的环绕图（`.para-float`），
  导致点不到（右键、拖动）；环绕图设 `position: relative; z-index: 1`。
- **对话框中的撤销**：只要有 `dialog[open]`，编辑页就不处理 Ctrl+Z / Ctrl+Y（焦点可能已离开对话框）。
  表格编辑器在窗口上监听并维护自己的撤销记录；其他对话框用输入框原生的撤销。
- **行内块与首行缩进**：预览中设为 `display: inline-block` 的元素（如加下划线的公式外框）会继承段落首行缩进，
  必须设 `text-indent: 0`，否则前面多出空白。
- **导出文件名**：`shared/export-name.ts`，`(T)名称.docx` / `(S)名称.docx`，主进程与导出对话框共用。
- **多个教学案（标签页）**（`state/workspace.ts`、`state/useWorkspaceFiles.ts`、`TabBar.tsx`）：工作区是一组标签页，
  每个标签页持有一份完整的 `EditorState`（内容、撤销历史、选中项……），编辑动作经 `{ type: 'doc', id, action }`
  交给对应标签页的 `editorReducer`。同一文件只开一个标签页。App 只挂载当前标签页的 Editor（`key={tab.id}`），
  切换时记住并恢复预览滚动位置。关闭有修改的标签页时由主进程 `askSaveChanges` 询问；关闭窗口时主进程按
  `setWindowState` 传来的 `dirtyTitles` 提示，选“全部保存”后渲染进程依次保存。
  **注意类名**：编辑页三栏区域的类名是 `.workspace`，外层标签页容器用 `.app-shell`（曾因重名导致三栏布局被覆盖）。
- **首页**（`home/`）：`HomeSidebar`（最近、教学案库、本地位置与可展开的文件夹树，只在离当前文件夹最近的位置下展开）、
  `FileTable`（右键菜单 `ContextMenu`、就地重命名、Enter / F2 / Delete）。主进程 `main/files.ts`：列文件夹（只列子文件夹、
  .tplan、.docx，跳过隐藏与系统文件夹）、磁盘、重命名（教学案同时改文件中的名称，最近打开记录跟着改）、文件名检查。
  删除用 `shell.trashItem` 移到回收站。首页导出用 `readProject`（只读取，不记入最近打开）。
- **选项间距方案**（`core/model/option-stop-schemes.ts`）：内置方案 + 用户方案（主进程 `settings.json` 的
  `optionStopSchemes`，读取时校验整理）；渲染进程用 `state/optionStopSchemes.ts` 共享。工程里仍只存列位置本身。
- **难度**：数据中通常只存等级 `difficulty`；题干前缀显示哪些由 `project.layout.difficultyDisplay` 决定，大纲始终两者都显示。星级由预设 `difficulty.levels`（A=1、B=2、C=3 星）得出（`difficultyOf`），
  只有 `stars` 时换算成等级，两者不一致时以等级为准。导入时题干开头的 ★ 换算成等级。
- **字体**只分四个大类（`FontFamily`：宋体/黑体/楷体/仿宋），对照表在 `core/document/fonts.ts`。
  文字的 `marks.font` 优先，其次段落的 `format.font`，再次样式的 `fontRole`。导出只写东亚字体（`w:eastAsia`）。
  `styles.ts` 中各样式的 `fontRole` 必须与模板 styles.xml（含主题字体）一致，`test/fonts.test.ts` 会逐个对照——
  此前综合题背景（模板为楷体）、大标题和栏目标题（模板为宋体加粗）就是因为不一致，预览与导出字体不同。
- **导入整理字体**（`core/import/normalize-fonts.ts`）：题库文档几乎每段都显式标了宋体。与字段样式相同的字体不记录，
  整段同一字体提升为段落字体，只有真正混排的才留在文字上。导入还识别文字颜色（黑色、自动视为无色）。
- **选项列位置**：`project.layout.optionStops`（题目可在 `layout.optionStops` 另设），单位 twip，相对左页边距。
  导出时段落制表位是叠加在样式制表位之上的，所以 `docx-writer` 会清除模板“题目 选项”样式自带但未使用的
  制表位（`TEMPLATE_OPTION_TAB_STOPS`）。第 6 版前的工程迁移为模板原位置（11/20/29 字），新建工程用 13/24/35 字。
- 属性面板的文本框（`RichTextField`/`ParagraphField`）**只在挂载时读一次行内对象**，在别处改了其中的图片或公式后，
  必须让它重新挂载（例如选项行的 key 含 `optionImageSignature`），否则之后一打字会把改动还原。

### 修改数据结构时的纪律

1. 改 `types.ts` 同时改 `schema.ts`（不同步会编译失败）。
2. 递增 `CURRENT_FORMAT_VERSION`，在 `format.ts` 的版本记录里写一行，需要时在 `codec.ts` 的 `migrate` 补迁移；
   **旧工程必须能打开，排版效果不变**（已有 v1→v2、v2→v3 迁移与测试）。
3. 新增块类型要同步：`build.ts`、`Outline.tsx` 的 `describe()`、`Inspector.tsx` 的 `BLOCK_NAMES` 与表单、
   `AddMenu.tsx`、`store.ts`（如涉及按 ID 查找，用 `findBlock` / `mapBlockById`，它们会进入综合题的小题）。

## 5. 功能现状

已完成：首页与教学案库（`.tplan` 独立文件）、新建/打开/保存、三栏编辑界面（栏宽可拖）、分页预览与实时重排、
教师版/学生版切换、页眉（Logo/电话/水印）可编辑、Word 导入（含 MathType、EQ 域、形状示意图）、
Word 导出（模板化，教案/学案）、公式可视化编辑（MathLive + 仿 WPS 工具栏）、版式设置（整题同页/允许跨页，

## 7. 测试与验证方法

### 单元测试

`npm test`。涉及导入导出的测试直接读 `reference/samples/` 里的真实文档。
改了排版规则、导入识别或导出，先看是不是改坏了这些回归测试，再决定是改代码还是改预期。

### 在真实界面里验证（AI 对话的沙箱环境）

沙箱里没有显示器，用 xvfb + Playwright 的 Electron 驱动。**这套做法在本项目里反复用到，关键经验：**

- **必须用开发模式测试**：用户用 `npm run dev`，React StrictMode 会重复执行 effect，曾因此出过“图片全不显示”的事故，
  而打包版本测不出来。构建命令：`NODE_ENV=development npx electron-vite build --mode development`，
  然后用 Playwright 启动 `electron` 加载项目目录（`args: ['--no-sandbox', '<项目路径>']`）。
- Playwright 在沙箱中位于 `/opt/npm-tools/node_modules/playwright`（用 `require('/opt/npm-tools/node_modules/playwright')`），
  如不存在先确认环境再决定怎么装。运行：`xvfb-run -a -s "-screen 0 1600x1000x24" node 脚本.cjs`。
- 用 `app.evaluate(({dialog}) => { dialog.showOpenDialog = async () => ({canceled:false, filePaths:[...]}) })`
  替换文件对话框，才能自动化“导入/导出/选择文件夹”。
- 用环境变量 `HOME=/tmp/某目录 XDG_CONFIG_HOME=...` 隔离测试用的教学案库与设置，避免互相污染。
- `electron-vite dev` 起的服务器会随它启动的窗口一起退出，不适合反复测试，用上面的开发模式构建更省事。
- 截图后用 `view` 查看；给用户看的截图复制到 `/mnt/user-data/outputs/` 再 `present_files`。
- 导出 Word 后用 `python3 /mnt/skills/public/docx/scripts/office/validate.py 文件.docx` 校验结构。
  LibreOffice 可转 PDF 看版式，但**显示不了 Word 公式**，不能以它判断公式是否正常。
- 用 `pdftotext`/`pdftoppm` 对照原文文档的渲染结果，核对导入是否忠实。

### 其他经验

- 浏览器对 SVG 字号有上限：SVG 里文字不要直接用 EMU 当字号（9 磅 = 114300 会被截断成小点），
  用“磅”书写再整体放大（见 `drawing-svg.ts`）。
- `xmldom` 的 `getElementsByTagNameNS` 不支持通配符；MathML 里 temml 用 `<menclose>` 表示上划线/下划线，
  Chromium 不支持，需要引入 `temml/dist/Temml-Local.css`（已在 `main.tsx` 引入）。
- 数学键盘必须放在公式弹窗内部（`<dialog>` 外的内容不可点击）。

## 8. 协作约定

- **每个功能：先分析 → 实现 → 单元测试 → 在真实界面里实测并截图 → 提交推送**。工具调用有次数上限，
  回合结束前一定要提交并推送，沙箱环境会在对话之间重置，没推送的工作会丢。
- 提交信息用中文，写清做了什么与为什么；README 的“使用说明”随功能更新。
- **依赖版本固定为确切版本，且只选发布满两周的版本**（`npm install --before=<两周前的日期>`；
  vitest 与 vite 8 有 peer 冲突时加 `--legacy-peer-deps`）。新增依赖后提醒用户 `npm install`。
- 许可证：避免 LGPL/GPL 依赖（软件要分发给其他老师）。
- 与用户沟通用中文；回复里先说结论，再说细节；坦诚说明哪些地方没能验证；
  需要用户确认的事（如 Word 中的效果）明确提出。
- 用户对界面细节要求高，常按 WPS/Word 的习惯来要求（例如公式工具栏仿 WPS）。
