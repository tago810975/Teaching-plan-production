# 开发交接

给接手本项目的开发者（包括新开的 AI 对话）。**开始任何工作前先读完这份文档**，再读 `README.md`
和 `docs/技术选型.md`。**专门制作格式预设 / Word 模板的对话请读 [`docs/模板制作指南.md`](模板制作指南.md)。**
**改界面样式、加组件或加主题前请读 [`docs/界面与主题.md`](界面与主题.md)。**

最后更新：第 17 版工程格式，537 个测试，4 个内置格式预设（物理教学案 V1.0、物理知识点手册 V1.0、物理题型整理 V1.0、数学教学案 V1.0），1 个内置 Word 模板；支持自制模板（教学案库\模板）；7 套界面配色主题（含 2 套风格主题）。

## 1. 项目是什么

教学案制作软件（桌面应用，先做 Windows，后移植 macOS）：导入题目 Word 文档 → 自动识别题目 →
在软件中编辑与排版 → 一份工程同时导出教师版（教案）与学生版（学案）Word。
用户是一位物理老师（墨帝教育），文档来自题库与组卷网，格式杂（MathType 公式、WPS 绘图、EQ 域、表格等）。

## 2. 技术栈与运行

Electron 44 + React 19 + TypeScript 6 + electron-vite；公式用 MathLive（编辑）、temml（LaTeX→MathML）、
自写的 OMML/LaTeX/MathML 互转；docx 读写直接操作 OOXML（JSZip + @xmldom/xmldom）；MathType 用 cfb 读 OLE。

```bash
npm install     # 每次 git pull 后都要执行，依赖常有新增
npm run dev     # 开发版
npm test        # vitest，全部应通过
npm run typecheck
npm run dist:win  # 打包 Windows 安装程序（release/），尚未正式发布
```

用户在 Windows 上用 `git pull` + `npm install` + `npm run dev` 测试，**所以每个功能做完必须提交并推送**。

## 3. 架构

```
工程数据 (Project)  ──build.ts──▶  文档中间表示 (DocIR)  ──▶  预览 (React)
                                                         └─▶  Word 导出 (docx-writer)
```

- **所有排版规则只写在 `src/core/document/build.ts`**（题号、选项分列、教师/学生版取舍、留白、跨页、
  图片位置、知识点、综合题、作业单、默写挖空）。预览与导出只读 DocIR，不得各自另写规则——这是“预览与导出一致”的保证。
- `src/core/` 是纯逻辑，不依赖 Electron 与 DOM，可直接用 vitest 测试。界面在 `src/renderer/`，
  文件读写在 `src/main/`，二者通过 `src/shared/ipc.ts` 定义的接口通信。

## 4. 关键机制

### 4.1 数据模型

- 内容块 `Block`：`title | section | topic | paragraph | question | knowledge | composite | worksheet`。
- **question**：stem / options / subQuestions / figures / answer / knowledgePoints / keyPoint / difficultPoint /
  analysis / difficulty / layout / numberStyle（`variant` = 变式题，题号 a. b. c. 接在上一道编号题之后）/
  review（审题）/ important（重点题）。审题与重点题是“题目可选项”：`resolveQuestionFields(project.layout, preset)`——
  工程 `layout.questionFields` 优先，其次预设 `questionFields`，都没有为关闭；关闭时 Inspector 不显示、`build.ts` 不排版，数据保留。
  排版：审题在教师版解析之前（`analysis` 样式，首段前加 `REVIEW_LABEL`【审题】）；重点题在教师版题干前加 `IMPORTANT_LABEL`
  【重点题】（颜色取预设 `keyPoint.marks.color`，加粗）。
  **composite**（综合题）：标题 + 可选背景与配图 + 小题（完整 question）+ 共用答案与解析。
  **knowledge**：标题 + 内容 + 插图 + 版式。**worksheet**：作业单（标题 + 姓名栏）。
- 三级标题（title / section / topic）可设 `pageBreakBefore`（从新的一页开始，文档开头的不另起）、`restartNumbering`。
- 富文本是 `RichParagraph[]`，段落是 `Inline[]`：文字（marks：加粗、倾斜、下划线、上下标、颜色、字体）/
  公式 / 图片 / 填空 / **表格**（独占一段，单元格内容又是富文本，合并单元格按 HTML 方式记录）。
- **公式同时保存 `omml`（Word 导入的原始）与 `latex`（软件中新建或改过的）**：未改动的公式导出时原样写回 OMML。
  公式可有 `bold` / `underline` / `color`（导出时 `math-marks.ts` 写进 OMML；下划线是整个公式下方的 `<m:bar>`）。
- **图片位置** `FigurePlacement`：`below | right | right-items | below-item | below-all | free`；选项图片就是选项内容里的
  行内图片。
- 难度：数据中存等级 `difficulty`（A/B/C），星级由预设得出；题干前缀显示什么由 `layout.difficultyDisplay` 决定。
- 题目总数按题号计（`countQuestions`）：独立题目与综合题的每道小题各算一道。

**修改数据结构时的纪律**：

1. 改 `types.ts` 同时改 `schema.ts`（不同步会编译失败；表格的递归结构对 inline / richParagraph / tableInline 显式标注了类型）。
2. 递增 `CURRENT_FORMAT_VERSION`，在 `format.ts` 的版本记录里写一行，需要时在 `codec.ts` 补迁移；**旧工程必须能打开，排版效果不变**。
3. 新增块类型要同步：`build.ts`、`Outline.tsx` 的 `describe()`、`Inspector.tsx`、`AddMenu.tsx`、`BlockQuickMenu.tsx`、
   `store.ts`（按 ID 查找用 `findBlock` / `mapBlockById`，它们会进入综合题的小题）。

### 4.2 排版、样式与预设

- 样式数值在 `core/document/styles.ts`（`STYLE_SPECS`），**必须与模板 styles.xml 一致**；`test/fonts.test.ts`
  逐个对照字体与颜色（含 basedOn 继承与主题字体）。曾因不一致出过三次“预览与导出不同”。
- **格式预设**（`project.presetId`）决定：文档类型 `kind`（`lesson` 教学案 / `handbook` 知识点手册 / `typeSummary` 题型整理）、是否显示题号 `numberQuestions`、三级标题格式
  （`presetStyles` → `DocIR.styles`，导出时 `heading-styles.ts` 写回模板同名样式）、栏目名、作业单、颜色、“重点”格式、
  导入整理规则、默写挖空 `dictation`、难度等级、页眉是否加“(教案)/(学案)”。其余样式所有预设共用。字段全表见模板制作指南。
- **默写挖空**（`build.ts` 的 `blankKeyPoints`）：学生版中加粗且为指定颜色的文字与公式换成下划线空白，表格内也挖。
- **作业单**：段前分页的大标题、空行、姓名栏（制表位 + 下划线）、空行，其后题号从 1 开始。
- **选项列位置**：`layout.optionStops`（题目可单独设），单位 twip；用户方案存于本机 `settings.json`。
  导出时清除模板“题目 选项”样式自带的未用制表位（`TEMPLATE_OPTION_TAB_STOPS`）。
- **字体**只分四大类（宋 / 黑 / 楷 / 仿宋）：文字的 `marks.font` 优先，其次段落 `format.font`，再次样式 `fontRole`。
- **预览分页**（`paginate.ts`）：“与下段同页”连成一组，**遇到段前分页的段落就截止**（否则紧跟在标题后的标题不另起一页）；
  含表格的段落整块分页；普通段落可按行拆分。
- **知识点重点难点汇总**（`core/document/points.ts`，样张见 `reference/samples/知识点重点难点汇总/`）：按栏目列出每道题的
  知识点、重点、难点、审题；有重点题 / 难点题的栏目分组（【重点题】【难点题】【其他题】）。导出对话框第三项，
  文件名 `(T)名称(知识点重点难点).docx`（`pointsFileName`）；是否默认勾选由首页“设置…”（`home/SettingsDialog.tsx`，
  settings.json 的 `exportPointsByDefault`，默认否）决定。
- **公式正体**（设置“公式中的字母用正体”，默认是，settings.json 的 `mathUpright`）：导出时 `math-marks.ts` 的 `uprightOmml`
  给每个 `<m:r>` 加 `m:sty="p"`（粗体为 b，花体 m:scr 保持）；预览中 body 加 `math-upright`，关掉 `<mi>` 的自动斜体
  （`text-transform: math-auto`）。不改动公式数据。渲染进程共享状态 `state/mathUpright.ts`。
- **段落对齐**：数据 `format.align`（center / right，左对齐即清除）。属性面板格式工具栏的对齐按钮经 `useFormattable` 的
  `onAlign`（按光标所在行确定段）；预览选区工具条经 `set-align` 动作（按 `TextRange.path`）。表格单元格中不提供。
- **导出文件名**：`(T)名称.docx` / `(S)名称.docx`（`shared/export-name.ts`）。

### 4.3 导入

- 有“物理排版”样式的文档按样式识别；其他文档按题号、选项、【答案】【解析】等文字识别（`recognize.ts`）。
- **组卷网格式**（`zujuan.ts`）：无样式、以题组组织、上一组解析与下一组标题之间无空行。预处理按递增题号找小题、
  往回划出短标题与背景、插入“题组开始”标记（识别器新建综合题），答案区段落加标记（其中的“N．”不当新题），
  难度系数换算 A（≥0.7）/ B / C（<0.5）。
- 通用规则：`m:oMathPara` 只有在段中没有别的内容时才是行间公式（组卷网把每个公式都包在其中）；
  共用答案的题号可紧跟“】”；EQ 域与 OMML 公式保留红色加粗（默写挖空靠它）；表格读成表格（gridSpan / vMerge）。
- 导入后：`normalize-fonts.ts` 去掉与样式相同的字体（含表格单元格）；`preset-rules.ts` 合成作业单、换算星级、改写标签、整理解析颜色。
- 知识点手册（`recognize-handbook.ts`）：大标题 + “一、”知识点，不识别题目。

### 4.4 编辑与交互

- **撤销 / 重做**（`state/store.ts` 的 `reduceAt`）：每次改动前记录快照，最多 200 步，同一处连续修改（`mergeKey`）
  1 秒内合并。撤销后 `revision + 1` 让属性面板重新读取并恢复光标。**只要有 `dialog[open]`，编辑页就不处理撤销**
  （焦点可能已离开对话框）；表格编辑器有自己的撤销记录。新增会修改工程的动作时，需要合并连续修改就在 `mergeKey` 加一项。
- **属性面板的输入框只在挂载时读一次**行内对象：在别处改了内容（预览改格式、拖列宽、答案位置切换……）后，
  必须 `revision + 1`（或 `refresh-inspector`），否则之后一打字会把改动还原。
- **格式工具**（`panels/FormatToolbar.tsx`）：B / I / U / 颜色 / “重点”（组合格式），作用于输入框选中的文字，改写 ⟦⟧ 标记。
- **预览中选中文字改格式**（`preview/SelectionToolbar.tsx`）：文字带来源 `DocRun.src`，选区换算为 `TextRange`，
  `format-range` 动作用 `formatParagraphRange` 修改。有选区时点击预览不跳到输入框。
- **右键快捷窗口**：预览段落 / 大纲条目 → `BlockQuickMenu`（难度、选项排布、同页、留白、新页、题号、答案位置、移到、
  上移下移删除）；预览图片 → `ImageQuickMenu`（位置、宽度、顺序、删除；选项图片的统一大小）。图片右键在 `FigureImage`
  中阻止冒泡，不弹题目窗口。图片设置规则与属性面板共用 `panels/figure-options.ts`。
- **综合题答案位置**（`composite-answers.ts`）：“分到各小题”按连续递增题号拆共用答案与解析，“集中在最后”按全卷题号合并；
  真的搬动内容，可撤销。
- **题目跨综合题移动**（`move-question.ts`）：上移 / 下移到边缘即移出或移入；快捷窗口“移到”；大纲拖放
  （`useOutlineDrag.ts`，综合题末尾按指针左右区分放进或放后，插入线缩进表示放进）。
- **表格**：`panels/TableEditor.tsx`（单元格输入、格式工具、合并拆分、增删行列、列宽、自有撤销）；预览中拖动竖线改列宽
  （**移动与松开在 window 上监听**，拖动中表格可能被重新创建）。

### 4.5 墨案导入（老教学案系统迁移）

公司原来的教学案系统“墨案”（https://moan.modijiaoyu.com，Vue 2 + iView，公式用 KaTeX）中的教案无损迁移进来。

**为什么不从 PDF 导入**：墨案导出的 PDF 是无头 Chrome 打印的网页，文字层里 KaTeX 的“≠”只剩“=”、分数拆散颠倒、
结构只能靠版式猜。

**数据接口**：墨案的数据全部走 **socket.io v2**（`wss://server.modijiaoyu.com/socket.io/?EIO=3&transport=websocket`），
不是 XHR / fetch（前几次采集“0 条”就是这个原因）。每次请求的参数都带 `token`（网页登录后的令牌）。用到的：
- `moan-teaching-plan` 的 `show` `{ id, token }`：整份教案，结构见 `core/import/moan/convert.ts` 开头注释
  （卡片 type_id 3 文字 / 5 知识点 / 1 题目；name 题干、review_topic 解析、answer 答案、child 变式题、blankArea 留白、
  paging 换页、isImportant 重点、difficultyLevel_id 1～5 级难度）。富文本是 HTML，公式写作 `$…$`；
- `moan-teaching-plan` 的 `list` `{ folder_id, hadChild: 1, user_id: '', token }`：文件夹中的教案；
- 文件夹名称来自网页请求 `teaching-plan` 的 `folder-sub-list` 等的回应（`content.folders`）。

**流程**（`main/moan-window.ts`）：首页“从墨案导入…”或菜单“文件 → 从墨案导入…”打开墨案窗口（会话分区 `persist:moan`，
登录保留）。打开教案时询问是否导入（也可用窗口菜单“导入 → 导入当前教案”Ctrl+I）；“导入当前文件夹的全部教案”用网页最近一次
列出的文件夹。`main/moan-import.ts`：在页面中发 socket.io 请求（`moan-page-scripts.ts` 的 `socketCallScript`，页面来源
与网页相同）→ 下载图片（腾讯云 COS，`readImageInfo` 读尺寸）→ `convertMoanPlan` → `createProject`（数学教学案 V1.0，
页眉右侧为教案名“：”之前的部分，难度显示关闭）→ 保存到“教学案库\\墨案导入[\\文件夹名]”，单份导入后在主窗口打开。

**令牌**：预加载脚本 `preload/moan.ts` 给页面的 XHR / fetch / WebSocket 套一层记录；其中 socket.io 帧交给
`core/import/moan/session.ts` 得到服务器地址、令牌、当前文件夹，**只在内存中**。同一份记录交给 `CaptureRecorder`，
只有点“导入 → 保存诊断文件”才写文件，写入前隐去凭证（含 socket.io 帧里的 `"token"`；第 3 次采集曾因此泄露令牌，已修复）。

**转换规则**：栏目标题 = 只有一段、加粗大字或预设栏目名的文字卡片；知识梳理中的文字卡片也按知识点；题干末尾依次以
A. B. C. 开头的段落为选项（选择题），有“___”为填空题，否则解答题；只有图片的段落作为题图（下方）；
解析中“审题：…”一段拆进 `review`（`splitReview`，同一段里的“讲解提要”之后归还解析），其余解析前加“【解析】”；
isImportant → `important`；变式题 `numberStyle: 'variant'`（题号 a. b. c.，导出时取消自动编号、写成文字加制表符）；
墨案条目 id 与原始标记存在 `source.moan`。

开发与测试：环境变量 `MOAN_START_URL` 指向本机模拟页面；`globalThis.__moanImportCurrent()` / `__moanImportFolder()` /
`__moanSaveDiagnostics()` 触发窗口菜单的动作。两者只在未打包时生效。模拟服务器要实现 socket.io 握手
（0{…}、40、40/命名空间,）和 42 / 43 确认帧。真实教案样本：`test/fixtures/moan/show-3829.json`。

### 4.6 界面框架

- **多标签页**（`state/workspace.ts`、`useWorkspaceFiles.ts`、`TabBar.tsx`）：每个标签页一份完整 `EditorState`；
  只挂载当前标签页的 Editor；关闭时询问保存；关窗口时列出所有未保存的。外层容器类名 `.app-shell`
  （编辑页三栏是 `.workspace`，曾因重名覆盖布局）。
- **标签页切换的性能**：最近使用的 `KEEP_ALIVE`（4）个标签页的编辑器保留着，后台的加 `.is-inactive`（隐藏、`inert`、尺寸不变），
  切回来时不必重新排版、测量分页、渲染（40 页约 1.2 秒 → 0.1 秒）。**后台编辑器不得响应全局快捷键与菜单命令**
  （Editor 的 `inactive`）；全局查找预览元素时要限定当前的（`.app:not(.is-inactive)` 或 `data-tab`）。
  图片 blob URL 按资源 ID 全局共享、首次渲染时同步备好（`preview/assets.ts`）；LaTeX 公式的 MathML 也按内容缓存。
- **首页**（`home/`）：参照 WPS，左侧栏（新建、打开、最近、教学案库、本地文件夹树），右键菜单（打开、导出、重命名、删除到回收站），
  失效项可移除。主进程 `files.ts` 负责列文件夹与重命名。
- **设置**（首页左侧栏“设置…”，`home/SettingsDialog.tsx`）：配色、教学案库位置、导入时默认格式预设、导出 Word 的默认选项，都存在 settings.json。
- **配色主题**：七套（青灰、暖纸、雾蓝、素白、深色，以及风格主题“赤黑”“月潮”）。设计约定、各主题的风格、页面切换过场的机制
  与踩过的坑都在 [`docs/界面与主题.md`](界面与主题.md)。
- **预览的绘制性能**：缩放比例在绘制前同步算好（否则打开时先按 100% 画一帧再跳）；预览区预留滚动条位置；屏幕外的页面
  `content-visibility: auto` 跳过绘制；编辑器页面不做整页进入动画。改预览或过场前先看《界面与主题》第 7 节。
- **导出完成提示**：右下角浮动卡片，8 秒后自动关闭，鼠标停留或焦点在内时暂停，打开文件出错时不关。

### 单元测试

## 8. 踩过的坑（改相关代码前先看）

- **预览缩放用 transform，不用 CSS zoom**：分页在不缩放的测量区中测量断行；页面若用 `zoom` 缩放，浏览器按缩放后的字号
  重新排版，断行与测量不一致（换行随窗口大小变化、跨页拆分的段缺字或重字），小字号绘制在 Windows 上还会带彩色边
  （加粗标题发绿）。现在每页外框 `.page-frame` 按缩放后尺寸占位，页面按原尺寸排版后 `transform: scale`；缩放比例在
  `.preview-pages` 的 `data-zoom`，拖动换算用 `previewZoom()`。
- **段落中块元素的外边距会穿过段落**（外边距合并）：行间公式、表格外框用内边距，否则选中时左侧红线在那里断开。
- **WPS 兼容**：浮动图片曾写成 `wrapText="left"` + `<wp:align>right` + `allowOverlap="0"`，Word 正常，WPS 却把图排到段落上方、
  文字不环绕。现在照用户在 WPS 中排好的文档写：`wrapText="bothSides"`、水平位置用 posOffset、`allowOverlap="1"`、
  左右间距 9 磅（`FLOAT_GAP_EMU`，预览同值）。**改导出写法时以 reference/samples 中用户自己的文档为准**，并请用户在 WPS 中确认。
  **根本原因是“段中不分页”**：WPS 遇到带 `keepLines` 的段落里有浮动图片，就把图片排到段落上方、文字不环绕
  （用户用四种设置的对照文档确认：只有 keepNext 或都不设时正常）。导出时含浮动图片的段落不写 `keepLines`，
  只保留 `keepNext`。排查 WPS 问题时，做一份只改一个变量的对照文档请用户打开，比反复猜测快得多。
- **文档网格**：模板 docGrid 每行 15.6 磅，“物理排版 题目”（题干首段）对齐网格，其余样式关闭了对齐。预览必须照此计算行高
  （`styles.ts` 的 `snapToGrid`、`lineHeightFor`），否则题干行比 Word 矮 14%，锚定在题干上的右侧 / 自由图导出后偏上
  （第 17 版迁移把旧工程中这些图的偏移乘以 8/7）。题干中有高公式的行，Word 会再多占一格，预览按内容撑高，仍有小差别。
- **墨案的数据走 socket.io（WebSocket）**，不是 XHR / fetch；凭证隐去要处理 socket.io 帧格式 `42/命名空间,1[…]`。
- **沙箱预加载脚本不能共用模块**：有两个预加载入口（`index`、`moan`）时，两者都 import 的模块会被拆成公共 chunk 并
  `require('./chunks/…')`，而沙箱预加载只能 require `electron`，主窗口会因此打不开。`preload/moan.ts` 只 import `electron`，
  通道名在本文件里重复定义，测试检查两处一致。

- 预览中 `display: inline-block` 的元素会继承段落首行缩进，必须 `text-indent: 0`（公式下划线外框曾多出两个字的空白）。
- 段落是 `position: relative`，后面的段落框会盖住前面段落的环绕图，点不到；环绕图设 `position: relative; z-index: 1`。
- 拖动类交互的移动与松开监听放在 window 上（元素可能在拖动中被重新创建）。
- 文本框中的按钮变为不可用时焦点会离开对话框，此时的 Ctrl+Z 曾被当作整个教学案的撤销、把表格编辑器关掉。
- 浏览器对 SVG 字号有上限：SVG 里文字用“磅”书写再整体放大（见 `drawing-svg.ts`）。
- `xmldom` 的 `getElementsByTagNameNS` 不支持通配符；temml 的 `<menclose>` 需要 `Temml-Local.css`。
- 数学键盘必须放在公式弹窗内部（`<dialog>` 外的内容不可点击）。
- **界面样式与主题**的约定和坑（预览打开时跳一下、切换卡顿、菜单横向滚动条、`::-webkit-scrollbar` 不生效、过场图形透出幕布等）
  集中在 [`docs/界面与主题.md`](界面与主题.md) 第 7 节，改界面前先看。要点：颜色与数值用 `app.css` 顶部变量；风格主题的规则限定在
  各自的 `data-theme` 之下；大块内容的动画只用透明度与位移；过场动画加在独立元素的 `transform` / `opacity` 上。
