# 从图片导入题目：技术选型与实现

## 结论

识图由 AI 完成（老师常用的 WorkBuddy，或任意能识图的 AI），软件负责**格式约定、检查、校对、框选插图、导入**。
AI 把图片转写成约定格式的文字（`$LaTeX$` 公式、`[图N]` 插图占位），文字交给与导入 Word 相同的识别器。

分两步：

1. **公共部分（已完成）**：格式说明 `FORMAT_GUIDE`、`importText` / `checkText`（`core/import/text-import.ts`），
   “从图片导入”窗口（`renderer/src/import/ImageImportDialog.tsx`）：图片（选择 / Ctrl+V / 拖入）、拖框框选插图、
   复制给 AI 的指令、粘贴识别结果、即时检查（题数、无法转换的公式、未框选的插图、【?】）、导入。
2. **WorkBuddy 自动化（待做）**：见下。

## WorkBuddy 探针实测（2026-11-15，`tools/workbuddy-mcp-probe.js`）

- 配置文件 `C:\Users\<用户>\.workbuddy\mcp.json`，格式 `{"mcpServers": {名称: {"command", "args"}}}`（stdio）。
  软件可以自动写入这份配置（“连接 WorkBuddy”）。
- **不支持 MCP 采样（sampling）**：对话中的连接 `capabilities` 为空，软件不能主动请 WorkBuddy 的模型识图。
- **AI 能调用我们的工具；模型能看到工具返回的图片**（返回红色测试图，答出“红色”）。
- 工具进程**不在隔离环境**：与用户同一账户，可读写用户目录、可连接本机端口。
- WorkBuddy 自带 Node（`.workbuddy\binaries\node\...`），`"command": "node"` 即可，老师电脑无需安装 Node。
- 有“技能”“连接器”“专家”；环境变量中有 `WORKBUDDY_APP_DEEPLINK_SCHEME`（可能可由外部唤起，格式待查）、
  `WORKBUDDY_VLM_*`（内部看图模型，**无公开文档，不直接调用**）。

## 第 2 步的设计（待实现）

1. 软件里“连接 WorkBuddy”：写入 mcp.json（只需一次）；MCP 服务为不依赖第三方库的 stdio 脚本，由 WorkBuddy 自带的 Node 运行，
   经本机端口（带随机口令，只接受 127.0.0.1）与正在运行的软件通信。
2. 老师在“从图片导入”窗口点“交给 WorkBuddy 识别”：软件登记这批图片为待识别。
3. 老师在 WorkBuddy 里点我们的技能（如“导入题目到教学案”）；若深度链接可用，由软件自动唤起。
4. 工具：`get_pending`（返回图片与 FORMAT_GUIDE）→ AI 识别 → `check_questions`（自查）→ `submit_questions`（交回）。
5. 软件收到结果填入窗口的文字框，老师校对、框选插图后导入（AI 不能直接改动教学案）。

## 其他方案（未采用）

- 软件直接接大模型接口（老师填密钥）：可作为以后的第三种方式。
- 本地离线 OCR（PaddleOCR / Pix2Text，Apache / MIT）：工程量大、安装包增加数百 MB；MinerU、Surya 为 AGPL/GPL，不能用。
