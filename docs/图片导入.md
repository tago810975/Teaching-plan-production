# 从图片导入题目：技术选型与实现

## 结论

识图由 AI 完成（老师常用的 WorkBuddy，或任意能识图的 AI），软件负责**格式约定、检查、校对、框选插图、导入**。
AI 把图片转写成约定格式的文字（`$LaTeX$` 公式、`[图N]` 插图占位），文字交给与导入 Word 相同的识别器。

分两步：

1. **公共部分（已完成）**：格式说明 `FORMAT_GUIDE`、`importText` / `checkText`（`core/import/text-import.ts`），
   “从图片导入”窗口（`renderer/src/import/ImageImportDialog.tsx`）：图片（选择 / Ctrl+V / 拖入）、拖框框选插图、
   复制给 AI 的指令、粘贴识别结果、即时检查（题数、无法转换的公式、未框选的插图、【?】）、导入。
2. **WorkBuddy 自动化（待做）**：见下。

## 常见图片类型（用户提供的 9 张，2026-11-15）与处理

讲义扫描（案例、模型解析）、教辅书页（原型题、笔记、考点剖析）、练习册（查漏补缺、填空式知识梳理、例题）。
转写样本与检查要求见 `test/fixtures/image-import/` 与 `test/text-import.test.ts`。识别前的整理（只用于文字导入，不改通用识别器）：

| 情况 | 处理 |
|---|---|
| “例1”“原型题11”“案例一”等标签 | 格式说明要求 AI 改为“1．” |
| 圈码小问①②③ | 转为（1）（2）（3）；原文已有（1）时，圈码是小问里的下一级，保留 |
| [解析]、［答案］ | 转为【解析】【答案】 |
| 填空横线 ___ | 转为填空（宽度按横线长度） |
| 图注“（第15题图）”“（例1图）”、“扫码看解析” | 去掉 |
| 讲解中的小标题“1.模型解析”“一、……” | 短、无句读的编号行作为小标题，不当题目 |
| 小问后面的选项 | 归到该小问（`recognize` 的 `optionsFollowSubQuestion`，只在文字导入时打开） |
| 小问与解析交错 | 重排为全部小问 → 【答案】→【解析】（各小问用（1）（2）分开），否则后面的小问被当成解析，学生版看不到 |

**WorkBuddy 实测（2026-11-15，用户提供的 9 张图一次转写）**：题号、圈码、方括号标签、选项、插图占位、讲解小标题都按格式写对，
没有解题或补答案。但用户**从对话气泡中选中复制**，拿到的是渲染后的结果：`$…$` 公式被拆成几行（分式先分母后分子，夹着零宽字符 U+200B），
“______”被当作加粗记号吃掉。对策：格式说明要求 AI 把结果放进代码块（不渲染，且有复制按钮）；粘贴内容中零宽字符多时提示；
单独一行的题号与下一行合并；去掉题号后的来源标注“（P823 T1）”（用户不需要保留题目标签）。
**第 2 步（MCP）不经过对话气泡，没有这个问题。**

**WorkBuddy 第二次实测（代码块复制）**：67 个公式全部为标准 LaTeX、都能转为 Word 公式；AI 按格式说明先列小问再统一解析。
修正：解析里用已出现的（1）（2）分段不再被当成小问交错（只有答案或解析之后出现新的小问编号才重排）；temml 在 `\mathrm{…}` 每个字母后
加的无宽度 `<mspace>` 不再转成空格（单位“rad/s”不再变成“r a d /s”）；续页的半道题由 AI 写一行【接上页】标出，单独成题并提示补全
（没有标出时会并入前一题的解析，无法区分）。

**已知限制**：题目的数据结构中小问没有自己的选项。文字导入时小问的选项作为小问里的普通段落（顺序正确，但没有图片选项的
统一大小、自动分列）；导入 Word 时仍归到整道题上（期中试卷分析中有 3 道这样的题）。要彻底解决需给小问加选项（数据格式、排版、编辑界面）。

## 导入知识点

工具栏“导入知识点 ▾”（Word 文档 / 图片），与导入题目并列。`core/import/as-knowledge.ts` 的 `recognizeAsKnowledge`：
内容前虚拟一个带“标题2”样式的“知识梳理”栏目，让识别器按知识栏目处理（“一、……”短标题后跟正文成为知识点，“1.”开头的行
不当题目），识别后去掉该栏目，零散正文合并成没有标题的知识点。Word（`importDocx` 的 `asKnowledge`）与文字导入
（`importText` 的 `asKnowledge`）都支持；图片导入用知识点版格式说明 `KNOWLEDGE_GUIDE`；WorkBuddy 任务带 `kind: 'knowledge'`，
取到的格式说明与检查都按知识点。导入结果的 `knowledgeCount` 用于提示“导入 N 个知识点”。

导入完成提示改为右下角卡片（与导出完成提示同样式）：没有需要留意的情况时 8 秒自动淡出，有时不自动关闭。

## 插图：软件自动框选（AI 只能用 [图N] 标出位置，不能返回图片）

`core/import/figure-detect.ts`（移植自 `tools/figure-detect-prototype.py` v2，不依赖 AI、不联网）：先认出文字行
（一行中连起来的字，主体是正常字号的字、紧密，允许分数线与括号），其余（一排排的 ×、长直线、零星的标注）为插图材料；
材料按距离合并、隔着文字行不合并，再在最宽的竖直空白处切开（并排的图），太小的碎片并回邻近部分；必须有图形笔画；
排除答题括号、彩色底标签、容器边框（笔记框）、二维码。在用户的 9 张常用图片上 22 张插图全部框对；测试样本 5 张
（`test/fixtures/figure-detect/`，预期结果来自原型）。

窗口中：图片放入后自动框选（长边超过 2400 像素先缩小），编号按阅读顺序（图片顺序，同一张图先上后下、先左后右），
与识别结果中的 [图1]、[图2] 对应；框可拖动、拖四角调整、删除，“重新自动框选”；随手拖的新框收紧到插图
（`snapToFigure` 用整页检测得到的候选块 `pieces`，取大部分面积在框内的——在小区域里重新判断会被框边切断的文字干扰）；
导入时用作选项的图（“A．[图2]”）去掉底部单独的选项字母（`trimBottomLabel`）。
自动框出与随手拖后收紧的框，四周各留约半个字高的空白（`padBox`，至少 4 像素、不超出图片）：贴着墨迹边缘裁出的图，
边缘的线条紧贴图片边界，像被切掉一点。检测本身（`detectFigures`）仍贴边，测试与原型一致。

**坑**：文件选择框点“取消”会发出 `cancel` 事件并冒泡到外层 `<dialog>`，被当成 Esc 关闭整个窗口（连同识别结果）。
窗口的 onCancel 只响应 `e.target === e.currentTarget`。（Playwright 对中文路径的 setInputFiles 也会触发这个事件。）

## 插图变清晰

选型（`tools/figure-enhance-prototype.py`，在用户的扫描图上对比）：AI 重绘 SVG 不能保证还原（位置、标注会画错）；
矢量描摹（VTracer）在小而模糊的图上丢失细线、虚线并毁坏文字；EDSR 每张 10～85 秒太慢；
**清理底色 + FSRCNN ×3** 不改变内容、明显更清楚，每张约 1 秒。

- `core/image/enhance.ts`：清理（闭运算估计纸张底色，只取接近纸色的值——大块深色填充不被提亮；接近纸色压成纯白，深色线条加深 30%；
  填充、彩色保留），面积不超过 400×400 的再 FSRCNN 放大 3 倍（亮度用模型，颜色双线性）。
- `core/image/fsrcnn.ts`：FSRCNN ×3 的 TypeScript 实现（无依赖）；参数 `fsrcnn-weights.ts`（Apache-2.0，Saafke/FSRCNN_Tensorflow，
  conv8 偏置由与 OpenCV 输出对比求得）。测试与 OpenCV dnn_superres 逐像素对照（平均差 < 0.3/255）。
- 界面：后台线程 `import/enhance.worker.ts`；导入窗口“插图变清晰”（默认打开），点选插图显示处理前后对比；导入时插图按 3 倍像素保存、
  显示尺寸按原图（打印更清楚）。属性面板题图 / 插图“变清晰”（SVG 不处理，可撤销）。
- 坑：页面的安全策略不允许 fetch blob 地址；资源格式由 `preview/assets.ts` 的 `assetMime` 查询。

## 线稿模式（已去掉）

曾做过“线稿”（压成纯黑线条，Sauvola 局部阈值、按线宽判断填充等），用户试用后认为清晰度提高不明显，已删除（2026-11）。
需要时可从 git 历史（提交 5845905）恢复 `core/image/lineart.ts`。

## 去白底

`whiteToAlpha`（color to alpha）：按偏离白色的程度定不透明度并还原颜色，叠在白底上与原图一致；偏离 60% 以上的完全不透明、
颜色不变（较浅的彩色线条在有底色处也是实色）；亮度 232 以上先渐变为纯白。`enhanceFigure(img, mode, { transparent })`，
mode 为 'none' 时只去白底（`core/image/transparent.ts`）。入口：导入窗口“去白底”（可与变清晰搭配，预览用棋盘格底）；右键快捷栏、属性栏“去白底”；
批量处理“去白底（N）”。

## 属性栏“添加题图 / 答案插图 / 解析插图 / 插图 / 背景配图”

与“从图片导入”同一个窗口（`ImageImportDialog` 的 `kind="figures"`）：只有图片区（选择、粘贴截图或拖入，自动框选、调整），
变清晰、去白底、一键加深与预览；不显示识别结果区与 WorkBuddy 识别、重绘。交回框选的插图（按阅读顺序），没有框时整张；
显示尺寸按截取的像素估算（宽不超过 6.5 厘米）。一张时放在右侧环绕（原来的默认），多张时放在下方。

## 一键加深与手动调整（扫描件发灰）

`core/image/adjust.ts`：`autoLevels`——非纸色像素亮度的 1% 分位（最深的线条）拉到 25（不压到纯黑，留层次），
90% 分位（纸色，不低于黑点 + 40、不高于 250）拉到白，三通道同一映射（色相不变、更鲜明）。用户的两张扫描页中插图的线条
1% 分位约 110～127（中灰），加深后约 25，阴影面仍有层次。`adjustPixels`——亮度、对比度 −100～100，饱和度 0～200
（0 为黑白）。都在清理、放大之前做（`enhanceFigure` 的 `autoLevels`、`adjust`）。

入口：导入窗口“一键加深”；右键快捷栏、属性栏“一键加深”“调整…”；批量处理“一键加深（N）”。
“调整…”打开 `figures/FigureAdjustDialog.tsx`：原图与调整后并排，滑块在缩小到 640 像素的图上实时预览，应用时按原尺寸处理（一步撤销）。

## 让 WorkBuddy 重绘插图为 SVG（可选，老师逐张核对后选用）

AI 重绘不能保证还原，所以只作为可选项：“从图片导入”中点“让 WorkBuddy 重绘插图”，在 WorkBuddy 说“重绘插图”；
AI 逐张提交 SVG（`submit_svg`），软件检查、净化后送回窗口（“已收到 k/N”，框上标“SVG”）；点选插图并排显示原图与 SVG，
老师选用哪一个（默认选 SVG）；选用 SVG 的以 `image/svg+xml` 导入，显示尺寸按原图，导出 Word 时栅格化。

- 提示词 `core/import/svg-redraw.ts` 的 `REDRAW_GUIDE`：忠实还原第一；配色以用户示例为准（白底、黑色轮廓与文字、
  品红 #E95283 矢量箭头、天蓝 #0599D9 虚线表示另一位置 / 辅助框、浅灰 #E6E6E6 填充、Times New Roman 斜体字母）；
  只允许基本 SVG 元素。字号与线宽按原图逐张换算（`redrawSizes`：字号 = 原图字高 ÷ 图宽 × 600，主线宽为其 1/8），
  写在任务说明中——固定字号会让小图重绘后字太小。
- `validateSvg`：去掉代码块与前后文字；必须是 <svg> 且有 viewBox（缺时由宽高补）；去掉不允许的元素、事件属性、外部链接；
  限 400 KB；不合格时把中文原因退回 AI 修正。
- 本机服务 `/redraw/pending`、`/redraw/submit`；MCP 工具 `get_figures_to_redraw`、`submit_svg`（每张交后告知还差哪几张）。

## 插图的变清晰与重绘：在编辑界面中使用

- 导入窗口：框左下角“重绘”开关逐张勾选，“让 WorkBuddy 重绘（N）”只交出勾选的（本来就清晰的图不用重绘）。
- 左键点击预览中的题图 / 插图：属性栏定位到这张图的设置（字段 `figure:<figures|answer|analysis>:<序号>`，
  答案、解析插图切到“仅教师版”），该行短暂高亮。插图组件的点击不再冒泡到段落；拖动、缩放后不算点击。
- 右键插图的快捷栏、属性栏插图列表：“变清晰”“WorkBuddy 重绘”。矢量图（SVG）两者都不可用。
- “批量处理插图”（大纲顶部）：`figures/FigureBatchDialog.tsx`，列出全部插图（`core/model/figure-refs.ts` 的 `listFigures`：
  题图、答案 / 解析插图、知识点插图、背景配图、综合题中小题的插图），勾选后变清晰或交给 WorkBuddy 重绘；
  SVG 回来后逐张对照选用，“应用”换成 SVG（高度按 SVG 的宽高比）。单张“WorkBuddy 重绘”也打开这里并立即交出。
- 替换图片用状态动作 `replace-figure-assets`（资源一并加入，一步撤销）；公用函数在 `figures/figure-actions.ts`。

## WorkBuddy 探针实测（2026-11-15，`tools/workbuddy-mcp-probe.js`）

- 配置文件 `C:\Users\<用户>\.workbuddy\mcp.json`，格式 `{"mcpServers": {名称: {"command", "args"}}}`（stdio）。
  软件可以自动写入这份配置（“连接 WorkBuddy”）。
- **不支持 MCP 采样（sampling）**：对话中的连接 `capabilities` 为空，软件不能主动请 WorkBuddy 的模型识图。
- **AI 能调用我们的工具；模型能看到工具返回的图片**（返回红色测试图，答出“红色”）。
- 工具进程**不在隔离环境**：与用户同一账户，可读写用户目录、可连接本机端口。
- WorkBuddy 自带 Node（`.workbuddy\binaries\node\...`），`"command": "node"` 即可，老师电脑无需安装 Node。
- 有“技能”“连接器”“专家”；环境变量中有 `WORKBUDDY_APP_DEEPLINK_SCHEME`（可能可由外部唤起，格式待查）、
  `WORKBUDDY_VLM_*`（内部看图模型，**无公开文档，不直接调用**）。

## 第 2 步：WorkBuddy 自动识别（已实现）

老师的操作：设置中“连接 WorkBuddy”（一次）→“从图片导入”中放图、点“交给 WorkBuddy 识别”→ 在 WorkBuddy 里说“导入题目”
→ 结果自动填入窗口，检查后导入。

- `src/main/workbuddy-bridge.ts`（不依赖 Electron，可测试）：本机 HTTP 服务，只监听 127.0.0.1、随机端口与口令，连接信息写到
  用户数据目录 `workbuddy-bridge.json`；接口 `/pending`（待识别的图片与格式说明）、`/check`、`/submit`。
- `resources/mcp/teaching-plan-mcp.cjs`（MCP 服务，stdio，无依赖，由 WorkBuddy 自带的 Node 运行）：工具 `get_pending_images`、
  `check_questions`、`submit_questions`；软件没运行、没有待识别的图片时给出明确提示。每次启动复制到用户数据目录 `mcp/`。
- `src/main/workbuddy.ts`：启动本机服务；“连接”在 `~/.workbuddy/mcp.json` 的 mcpServers 中写入 `teaching-plan`
  （`command: node`、脚本路径、`env.TEACHING_PLAN_BRIDGE`），保留其他连接器，第一次修改前备份为 `mcp.json.teaching-plan.bak`；
  任务登记（同一时间一批）、插图数更新、取消；收到提交时发给登记的窗口。
- 窗口：图片长边超过 2000 像素先缩小、JPEG 发送；等待时显示“请到 WorkBuddy 里说：导入题目”（可复制）；关闭窗口即取消任务。
- 测试 `test/workbuddy-bridge.test.ts`：照 WorkBuddy 的方式运行 MCP 脚本，覆盖取图、检查、提交、口令、软件没运行。

**待用户实测**：WorkBuddy 的 AI 是否按工具说明依次取图、检查、修正、提交；如果需要更短的触发方式，可以做成 WorkBuddy 的“技能”。

## 其他方案（未采用）

- 软件直接接大模型接口（老师填密钥）：可作为以后的第三种方式。
- 本地离线 OCR（PaddleOCR / Pix2Text，Apache / MIT）：工程量大、安装包增加数百 MB；MinerU、Surya 为 AGPL/GPL，不能用。
