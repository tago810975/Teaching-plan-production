# 模板制作指南

给专门制作“格式预设 / Word 模板”的对话（包括其他 AI）。**动手前先读完本文**，再读 `docs/开发交接.md`
的第 2～4 节（运行方式、架构、数据模型）。本文基于第 14 版工程格式、3 个预设（物理教学案 V1.0、
物理知识点手册 V1.0、物理题型整理 V1.0）、1 个 Word 模板（`physics-default`）写成。

---

## 0. 内置模板与自制模板（放在哪里）

| | 位置 | 谁来改 | 说明 |
|---|---|---|---|
| **内置模板** | 源码 `src/core/presets/*.json` + `resources/templates/<templateId>/`；安装后在安装目录 `resources/resources/templates/`（只读） | 开发者，随软件发布 | 预设 JSON 编译进程序；Word 模板由 `electron-builder.yml` 的 `extraResources` 复制到安装目录 |
| **自制模板** | “教学案库\模板\<id>\”，默认为“文档\教学案\模板” | 老师，在首页“模板…”中管理 | 升级软件不会覆盖；换教学案库时跟着走；教学案库扫描时跳过这个文件夹 |

自制模板的文件夹：

```
<id>/
  preset.json     格式预设（必需，字段同第 3 节；id 只能用小写字母、数字、连字符，不能与内置或其他模板相同）
  template.docx   Word 模板（可省：省略时用 preset.json 中 templateId 指向的内置模板；有则 Word 模板 ID 记为 user-<id>）
  header/         默认页眉 defaults.json 与图片（可省：省略时用内置 physics-default 的页眉）
  README.md       说明（可省）
```

- 启动时主进程（`src/main/user-templates.ts`）读取并校验：preset.json 用 zod 校验（错误译成中文），template.docx
  检查 `{{body}}` 与全部必需样式名（`src/core/template/check.ts`）。有问题的模板不载入，原因列在“模板…”对话框中。
- 界面启动时通过 IPC 取得用户预设并登记（`core/presets` 的 `setUserPresets`；主进程也登记一份），
  之后 `getPreset` / `allPresets()` 都包含它们。**界面代码要列出预设时用 `allPresets()`，不要用只含内置的 `PRESETS`。**
- “模板…”对话框：复制为新模板（id 加 `-copy`、名称加“（副本）”，连同 Word 模板与页眉一起复制，并写一份 README.md）、
  导出为 zip、导入 zip（preset.json 可在根目录或一层文件夹中，只收 preset.json / template.docx / README.md / header/ 下的图片与 JSON）、
  重新载入、删除（移到回收站）。
- 老师自制模板的推荐流程：复制最接近的内置模板 → 打开文件夹改 preset.json（name、标题格式、行距、栏目名……）→ 重新载入。
  **只改 template.docx 中正文、题目等样式的字号缩进，会让预览与导出不一致**（见第 1 节的边界），README.md 中也有提醒。
- 用自制模板做的教学案记录的是它的预设 id 与模板 ID；模板被删除后仍能打开（回到默认预设），导出时提示找不到模板。

## 1. 三样东西：格式预设、Word 模板、示例文档

| | 是什么 | 放在哪里 | 决定什么 |
|---|---|---|---|
| **格式预设** | 一个 JSON 文件 | `src/core/presets/<id>.json` | 文档类型（教学案 / 知识点手册）、三级标题的格式、常用栏目名、作业单格式、文字颜色、“重点”格式、导入整理规则、默写挖空、难度等级、页眉是否加“(教案)/(学案)” |
| **Word 模板** | 一个文件夹 | `resources/templates/<templateId>/` | 导出 Word 的全部样式（字体、字号、缩进、行距）、自动编号（题号、小问号、【答案】等标签）、纸张与页边距、页眉页脚版式、新建工程时的默认页眉 |
| **示例文档** | 用户提供的真实 Word 文档 + 分析 | `reference/samples/<名称>/` | 制作预设的依据；导入识别与回归测试直接读取它们 |

- 预设通过 `templateId` 指定用哪个 Word 模板。多个预设可以共用一个模板（两个现有预设都用 `physics-default`）。
- 工程文件（`.tplan`）里记录 `presetId`；打开时用 `getPreset(id)` 取预设，找不到时回到默认预设 `physics-v1`。
- 用户在“新建教学案”“从 Word 文档新建”时选择预设，首页可设“导入时默认格式预设”。

**一个关键的边界**（务必理解，否则会白做）：

> 目前**只有三级标题**（大标题 / 栏目标题 / 题型分组）的格式能由预设单独配置。其余 13 个样式（正文、题目、
> 选项、小问、答案、知识点、重点、难点、综合题题目与背景……）的格式写死在 `src/core/document/styles.ts`
> 的 `STYLE_SPECS` 里，所有预设共用，并且**必须与 Word 模板的 styles.xml 完全一致**（有测试逐个对照字体与颜色）。
>
> 所以：
> - 只是换标题格式、栏目名、作业单、颜色、导入规则、页眉文字 → **只写预设 JSON**；
> - 要换正文 / 题目等的字体、字号、缩进 → 需要**改代码**：让 `STYLE_SPECS` 也能由预设覆盖（参照 `presetStyles()`
>   对标题的做法，以及导出时 `export/heading-styles.ts` 把标题格式写回模板样式的做法），或为新模板另建一套样式表。
>   这属于开发工作，做之前先和用户确认。

## 2. 单位换算

| 单位 | 用在 | 换算 |
|---|---|---|
| twip（缇） | 段前段后间距、制表位、缩进、列宽 | 1 磅 = 20 twip；1 厘米 ≈ 567 twip；五号字一个字宽 = 210 twip |
| 半磅（half-point） | 字号 `sizeHalfPt` | 五号 10.5 磅 = 21；小四 12 磅 = 24；四号 14 磅 = 28；小二 18 磅 = 36 |
| EMU | 图片尺寸 | 1 厘米 = 360000 EMU；1 磅 = 12700 EMU |
| 颜色 | `color` | 6 位十六进制，不含 #，大写，如 `C00000` |
| 字体大类 | `font` | `song` 宋体 / `hei` 黑体 / `kai` 楷体 / `fang` 仿宋（导出时写 Windows 自带的字体名） |

A4 版心宽 10466 twip（约 18.46 厘米，约 49.8 个五号字），见 `core/document/units.ts`。

## 3. 格式预设 JSON：全部字段

校验规则在 `src/core/presets/index.ts`（zod），字段写错或缺少时程序启动即报错。以 `physics-v1.json` 为例：

| 字段 | 类型 | 说明 | 物理教学案 V1.0 | 物理知识点手册 V1.0 | 物理题型整理 V1.0 |
|---|---|---|---|---|---|
| `id` | 字符串 | 唯一标识，**发布后不能改**（工程文件靠它找预设） | `physics-v1` | `physics-handbook-v1` | `physics-typesummary-v1` |
| `name` | 字符串 | 界面显示名，格式“学科 + 类型 + 空格 + V版本” | 物理教学案 V1.0 | 物理知识点手册 V1.0 | 物理题型整理 V1.0 |
| `subject` | 字符串 | 学科 | 物理 | 物理 | 物理 |
| `description` | 字符串 | 一句话说明，显示在选择预设处 | | | |
| `templateId` | 字符串 | Word 模板文件夹名 | `physics-default` | `physics-default` | `physics-default` |
| `kind` | `lesson` / `handbook` / `typeSummary` | 文档类型（见下） | `lesson` | `handbook` | `typeSummary` |
| `numberQuestions` | 布尔，可省 | 题干前是否显示题号（省略为显示）；不显示时题干首行缩进两字，导出写 `numId 0` | — | — | `false` |
| `lineSpacing` | 对象，可省 | 默认行距（倍数，`heading` / `question` / `knowledge` / `body` 各项可省，范围 1～3）；工程的版式设置可另行设置 | — | — | 标题 1，其余 1.3 |
| `questionFields` | 对象，可省 | 题目可选项默认是否使用：`review` 审题、`important` 重点题（各项可省，省略为不使用）；工程的版式设置“题目可选项”可另行打开或关闭 | — | — | — |
| `header.variantSuffix` | 布尔 | 页眉右侧是否加“(教案)”“(学案)” | `true` | `false` | `false` |
| `header.left` | 字符串，可省 | 新建时页眉左侧文字（省略则用模板的） | — | 物理知识单 | 高中物理 |
| `headings.title / section / topic` | 对象 | 大标题、栏目标题、题型分组的格式（见下） | 宋体 18/14/10.5 磅加粗 | 同左 | 黑体 17.5/14.5/10.5 磅不加粗 |
| `sectionNames` | 字符串数组 | “添加”菜单中的预制栏目标题 | 知识梳理、例题精讲、课堂练习、课后练习、课堂总结 | `[]` | 例题、审题：……、解题：……、题后归纳 |
| `worksheet` | 对象 | 作业单模块（见下） | | （有，但手册中不显示） | （有，菜单中不显示） |
| `textColors` | 数组 | 格式工具的颜色按钮；不写 `color` 的一项表示“黑＝去掉颜色” | 红 C00000、黑、蓝 2F5597 | 同左 | 红、黑、蓝 1F4E79 |
| `keyPoint` | 对象 | “重点”按钮的格式（`bold`、`underline` 必须为 true） | 红色加粗下划线 | 同左 | 同左 |
| `import.renameLabels` | 对象 | 导入时改写的标签 | `{"【详解】":"【解析】"}` | `{}` | 同教学案 |
| `import.analysisColor` | `black` / `keep` | 导入时解析是否统一为黑色 | `black` | `keep` | `black` |
| `dictation` | 对象 | 学生版默写挖空（见下） | `enabled: false` | `enabled: true` | `enabled: false` |
| `difficulty.levels` | 数组 | 难度等级与星数、说明，从易到难 | A 1★ 简单、B 2★ 中等、C 3★ 难 | 同左 | 同左 |

内置的第四个预设 **数学教学案 V1.0**（`math-v1`，模板 `physics-default`，`kind: lesson`）与物理教学案 V1.0 基本相同，区别是：
栏目名为知识梳理 / 例题精讲 / 课堂练习 / 课堂总结 / 课后练习；难度分 5 级（A ★ 容易 … E ★★★★★ 难）；解析保留颜色；
`questionFields` 为 `{ "review": true, "important": true }`（审题、重点题默认打开）。从墨案导入的教案使用这个预设。

### 3.1 `kind`：文档类型

- **`lesson` 教学案**：识别题目、综合题、知识点、栏目（知识梳理 / 例题精讲……）；“添加”菜单有全部题型与预制模块
  （作业单、`sectionNames` 中的栏目）；组卷网格式的文档会先做题组预处理（`core/import/zujuan.ts`）。
- **`handbook` 知识点手册**：只有大标题与“一、二、三……”知识点，**不识别题目**（`core/import/recognize-handbook.ts`）；
  “添加”菜单只有知识点、正文段落、大标题。

- **`typeSummary` 题型整理**：导入时按教学案识别题目（含组卷网预处理）；“添加”菜单有全部题型，预制模块为
  整份骨架、审题注释框、“思维过程 / 书写过程”对照表与续表（`core/model/type-summary.ts`），以及 `sectionNames` 中的栏目。
  这些模块只用已有的块拼成：注释框是带底纹（`paragraph.shaded`）的正文段落，对照表是正文段落中的表格
  （`borderColor`、`valign`、`headerRow`，右栏单元格 `studentLines` 让学生版换成虚线格）。样张见
  `reference/samples/物理题型整理_放缩圆/ANALYSIS.md`（原为 LaTeX 编译的 PDF）。

新的文档类型（如“试卷”“讲义”）若识别方式不同，需要新增 `kind` 并写识别代码，属于开发工作。

### 3.2 `headings`：三级标题

```json
"section": { "font": "song", "sizeHalfPt": 28, "bold": true, "align": "left", "spaceBeforeTwip": 160, "spaceAfterTwip": 160 }
```

可选 `color`。`align` 只能是 `left` / `center`。预览直接按它显示；导出时 `heading-styles.ts` 把它写进模板中
同名样式（`物理排版 大标题` / `物理排版 标题2 知识梳理、例题精讲、课堂总结、课后练习` / `物理排版 题目类型`），
因此在 Word 里改这些样式时仍保持样式关联。**物理教学案 V1.0 的值与模板原样完全一致**（有测试），新预设可以不同。

### 3.3 `worksheet`：作业单

```json
"worksheet": { "titlePrefix": "作业单-", "fields": ["姓名", "教室", "正确率"], "tabStopsTwip": [3980, 7980], "blankChars": 8, "pageBreakBefore": true }
```

排版为“（分页）大标题 → 空行 → 姓名栏 → 空行”，之后题号从 1 开始；姓名栏各项之间用制表位对齐，
每项后面是 `blankChars` 个字宽的下划线。`tabStopsTwip` 的个数应为 `fields` 个数减一。

### 3.4 `dictation`：默写挖空

```json
"dictation": { "enabled": true, "colors": ["C00000", "FF0000"], "bold": true, "minChars": 4 }
```

学生版中，**加粗（`bold: true` 时）且颜色在 `colors` 中**的文字与公式换成下划线空白；相邻的合成一条；
长度为“字数 + 1”个字宽、至少 `minChars`（汉字算 1、字母数字算 0.5、公式按 5）。表格单元格中同样挖空。
标题不挖空。“重点”按钮设的格式（`keyPoint.marks`）应被这条规则覆盖，否则老师标的重点不会挖空。

## 4. Word 模板：硬性要求

### 4.1 文件夹结构

```
resources/templates/<templateId>/
  template.docx          导出用的模板（正文为 {{body}} 占位符）
  README.md              说明来源与生成方式
  header/
    defaults.json        新建工程时的默认页眉
    logo.png  phone-icon.png  watermark.png
```

`template.docx` 不手写：用 `scripts/build-template.mjs` 从一份排好版的示例文档生成——清空正文只留分节设置、
页眉文字换成占位符、页眉图片改名、删除正文图片。为新模板生成时，复制这个脚本改输入输出路径与页眉文字即可，
运行 `node scripts/build-template.mjs`。

### 4.2 `template.docx` 必须满足

1. **正文**：`document.xml` 的 `<w:body>` 里只有 `{{body}}` 与最后的 `<w:sectPr>`（纸张、页边距、页眉页脚引用）。
2. **页眉占位符**：`{{headerLeft}}`、`{{phone}}`、`{{headerRight}}`（各自在一个 `<w:t>` 里，不能被拆成多段）。
3. **页眉图片**的 `docPr` 名称：`tp:logo`、`tp:phone-icon`、`tp:watermark`（导出时据此替换或删除）。
4. **16 个样式名必须一字不差**（导出靠样式名找样式，导入也靠它识别）：

| 程序中的键 | Word 样式名 | 作用 | 现有格式 | 自动编号 / 标签 |
|---|---|---|---|---|
| `title` | 物理排版 大标题 | 大标题 | 宋体 18 磅 加粗 居中 | — |
| `section` | 物理排版 标题2 知识梳理、例题精讲、课堂总结、课后练习 | 栏目标题 | 宋体 14 磅 加粗 | — |
| `topic` | 物理排版 题目类型 | 题型分组 / 知识点标题 | 宋体 10.5 磅 加粗 | — |
| `compositeTitle` | 物理排版 综合题题目 | 综合题标题（如“材料一”） | 宋体 加粗 居中 | — |
| `compositeBackground` | 物理排版 综合题背景 | 综合题背景材料 | **楷体** | — |
| `body` | 物理排版 正文 | 正文、知识点内容、解析、题干续行 | 宋体 两端对齐 | — |
| `question` | 物理排版 题目 | 题干首段 | 宋体 | **题号**（现为编号第 3 级 `%4.`） |
| `subQuestion` | 物理排版 题目 次级题目 | 小问 | 宋体 | **小问号**（同一编号定义，现为第 6 级 `(%7)`） |
| `option` | 物理排版 题目 选项 | 选项 | 宋体，左缩进 480 twip | 自带制表位 2310/4200/6090（导出时会清除未用的） |
| `answer` | 物理排版 题目 解答 | 答案 | 宋体 **加粗** | 标签“【答案】” |
| `knowledge` | 物理排版 题目 知识点 | 题目的知识点 | 宋体 | 标签“【知识点】” |
| `keyPoint` | 物理排版 题目 重点 | 题目的重点 | 宋体 **红 C00000** | 标签“【重点】” |
| `difficultPoint` | 物理排版 题目 难点 | 题目的难点 | 宋体 红 C00000（基于“重点”） | 标签“【难点】” |

（正文、题干续行、解析三者共用“物理排版 正文”，所以是 13 个不同的 Word 样式名、16 个程序中的键。）

5. **自动编号**（`numbering.xml`）：
   - “物理排版 题目”与“物理排版 题目 次级题目”**必须挂在同一个编号定义（abstractNum）上**，并且该定义中
     **题号那一级与小问号那一级的 `<w:lvl>` 里要有 `<w:pStyle>` 指回这两个样式**——导出时 `docx-writer.ts` 的
     `findQuestionNumbering` 从“题目”样式的 `numId` 找到编号定义，再按 `w:pStyle` 找出两级；找不到时题号不会续编。
     现有模板：题号是第 3 级（文字 `%4.`），小问号是第 6 级（文字 `(%7)`）。
     “题号重新开始”（作业单、勾选了该选项的标题）靠新建一个从 1 开始的编号实例实现。
   - 【答案】【知识点】【重点】【难点】这 4 个标签是对应样式的编号文字（`numFmt` 为 `none`，`lvlText` 为标签文字），
     **导出的段落里不写这些字**。改标签文字只能改模板的编号定义（同时改 `styles.ts` 中的 `fixedLabel`，预览用它显示）。
6. **字体要写在东亚字体上**（`w:rFonts` 的 `w:eastAsia`，或 `w:eastAsiaTheme` 指向主题的中文字体），颜色写在样式
   自身的 `w:rPr` 里或经 `basedOn` 继承。测试按 `basedOn` 链与主题字体解析，与 `styles.ts` 逐个对照。
7. **文档网格与“对齐网格”**：模板的 `<w:docGrid w:type="lines" w:linePitch="312">` 让对齐网格的段落每行占
   15.6 磅（312 twip）的整数倍；关闭了对齐网格（`<w:snapToGrid w:val="0"/>`，沿 basedOn 继承，未设置时 Word 默认对齐）
   的段落按自然行高（宋体约字号的 1.3 倍）排。现有模板中**只有“物理排版 题目”对齐网格**。`styles.ts` 中各样式的
   `snapToGrid` 与网格行距 `DOC_GRID_PITCH_TWIP` 必须与模板一致（`test/fonts.test.ts` 对照）——曾因预览没有对齐网格，
   题干的行比 Word 矮 14%，锚定在题干上的右侧图片导出后位置偏上。

### 4.3 `header/defaults.json`

```json
{
```

## 5. 导入识别靠什么（制作预设时要对照示例文档检查）

`src/core/import/recognize.ts`：

1. **有“物理排版”样式的文档按样式精确识别**（样式名用正则匹配，见 `STYLE_ROLES`）。文档中出现“物理排版 题目”
   样式时，不再按“1.”题号识别题目（只认样式）。
2. **没有样式的文档按文字识别**：
   - 题号 `^\d{1,3}[．.、]`，选项 `A．`（选项可同行、可图片），小问 `（1）`；
   - 标签：【答案】、【详解】【解析】【分析】【点睛】【点评】【名师点睛】【拓展】【方法技巧】、【知识点】【考点】、
     【重点】、【难点】；难度 `【A】`～`【E】`，题干开头的 ★ 换算为等级；
   - 栏目标题（只认这些文字）：知识梳理、知识点梳理、知识清单、例题精讲、典例精析、典例分析、课堂练习、随堂练习、
     课堂检测、课后练习、课后作业、巩固练习、课堂总结、作业单、拓展提升、能力提升；
   - 知识类栏目中“1.”开头的是知识要点而非题目；“一、”开头的短段落是知识点标题。
3. **组卷网格式**（有【答案】【难度】且无“物理排版”样式）先由 `zujuan.ts` 预处理，见
   `reference/samples/组卷网_高中物理作业/ANALYSIS.md`。
4. 导入后按预设整理（`core/import/preset-rules.ts`、`normalize-fonts.ts`）：作业单合并、星级、标签改写、解析颜色、
   去掉与样式相同的字体。

新学科的示例文档如果用了上面没有的标签或栏目名，需要在 `recognize.ts` 中补充（开发工作，补测试）。

## 6. 制作流程

1. **收集示例**：请用户提供排好版的教师版（和学生版，如有）Word 文档。放进 `reference/samples/<学校或学期_主题>/`，
   文件名用 `教案_T_<主题>.docx` / `学案_S_<主题>.docx`（上传后文件名中的括号会变成下划线，按此规则重命名）。
2. **分析示例**，写 `ANALYSIS.md`（参照已有的四份）：
   - 段落样式统计（有没有“物理排版”样式、各样式的段数）；
   - 页眉文字、标题层级、栏目名、题号与选项写法、标签、颜色与加粗的用途；
   - 教师版与学生版的差别（挖空、删去的内容、手工改动）；
   - 公式类型（OMML / MathType / EQ 域）、图片、表格。
   分析方法：解压 docx，用 Python 正则统计 `word/document.xml` 与 `word/styles.xml`；
   导入后打印识别结果（参照 `test/handbook.test.ts`、`test/zujuan.test.ts` 的写法）。
3. **决定范围**：只需预设 JSON？还是需要新 Word 模板？还是需要改代码（见第 1 节的边界）？**先向用户说明再动手。**
4. **写预设 JSON**：复制最接近的现有预设改；在 `src/core/presets/index.ts` 中 `import` 并加入 `PRESETS` 数组。
5. **需要新模板时**：复制并修改 `scripts/build-template.mjs` 生成 `template.docx`，准备 `header/defaults.json` 与图片，
   写模板的 `README.md`；样式名、编号按第 4 节检查。若格式与 `styles.ts` 不同，先完成第 1 节所说的开发工作。
6. **写测试**（`test/<名称>.test.ts`）：用示例文档导入，断言识别结果（块的种类与数量、标题、关键段落）、
   教师版 / 学生版的排版结果（如挖空的位置与长度）、导出 Word 中的关键 XML。新模板还要仿照 `test/fonts.test.ts`
   对照模板与 `styles.ts` 的字体和颜色。`test/presets.test.ts` 中有预设名称列表的断言，需同步。
7. **在真实界面里验证**（方法见开发交接第 7 节）：用新预设“从 Word 文档新建”、切换教师版 / 学生版、导出 Word，
   截图给用户确认。沙箱里的 LibreOffice 显示不了 Word 公式，公式效果要请用户在 Word / WPS 中确认。
8. **更新文档**：本文第 3 节的表格、`docs/开发交接.md`、README 的“格式预设”一节；提交并推送。

## 7. 常见坑

- **样式名差一个字就失效**：导出找不到样式会报错，导入会当作无样式文档。“标题2”那个样式名很长，复制不要手打。
- **预览与导出不一致**，几乎都是 `styles.ts` 与模板 styles.xml 对不上（曾经出过：题干对齐文档网格而预览没有，右侧图片导出后偏上；综合题背景模板是楷体而预览是宋体；
  “难点”基于“重点”继承了红色而预览是黑色；大标题用主题字体）。测试会抓住字体与颜色，字号、缩进要自己核对。
- **用户用 WPS 查看导出文件**：Word 能正确显示的写法，WPS 不一定支持（曾有浮动图片所在段落带“段中不分页”，
  WPS 就把图片排到段落上方、文字不环绕）。
  导出写法尽量与示例文档（用户在 WPS 中排好的）一致，新模板的效果要请用户在 WPS 中确认。
- **段落制表位叠加在样式制表位之上**：模板“题目 选项”样式自带的制表位会干扰新的选项位置，导出时会清除，
  新模板若改了这些制表位，同步 `styles.ts` 的 `TEMPLATE_OPTION_TAB_STOPS`。
- **【答案】等标签是自动编号**：在 Word 里看到的标签文字不在段落文字中；导入时这些段落按样式识别，
  不能指望在文字里找到“【答案】”。
- **示例文档的学生版常有手工改动**（只做了一部分、加了提示语），只能作参考，不是程序要逐字生成的结果。
- **预设 `id` 发布后不能改**；显示名 `name` 可以改。改了字段结构要同步 `index.ts` 的校验与两个现有 JSON。
- **组卷网等题库下载的文档**每个公式都包在 `m:oMathPara` 里、没有样式、标签与我们自己的文档不同——先看
  `reference/samples/组卷网_高中物理作业/ANALYSIS.md` 了解程序已经处理了哪些情况。
